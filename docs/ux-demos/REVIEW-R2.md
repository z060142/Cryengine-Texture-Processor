## 第一輪：五理念案

- **R2-1 流程**（落選）：swimlane stepper 理念清晰，但線性隱喻與實際
  「改一組→重轉→再看」的反覆迭代相斥；改東西要逆著 stepper 走，
  8 個階段頁的導航成本高。
- **R2-2 空間**（晉級）：最直接回應業主「模型/貼圖分開子頁面」原話，
  現行 workbench 的自然演化，egui 遷移成本最低。弱點：Lab 工具間與
  資產脫節、Queue 分頁讓進度離開視野。
- **R2-3 選中**（晉級）：資產中心，四個新功能天然各就各位（選誰配誰）。
  弱點：批次操作與單選 inspector 打架、預設空白、全域動作藏齒輪裡。
- **R2-4 模組**（落選）：卡片儀表好看，但跨模組工作流（隨模型導出貼圖）
  無家可歸；進出全螢幕模組的導航摩擦大；1280×800 下首頁半屏空白。
- **R2-5 預覽**（晉級）：反儀表板最徹底（預設全折疊）、DCC 手感、
  底部 work center 強。弱點：折疊預設 = 每次找參數要翻。

## 第二輪：六改進案

- **2a 空間+連結**：Send-to-Lab + 麵包屑 + 迷你佇列，痛點修復到位，
  但 Lab 作為獨立空間的根本脫節仍在——被 2b 的做法蓋過。
- **2b 空間+子分頁**：解散 Lab，工具跟資產住（Textures[Convert|PBR]、
  Models[Export|Proxy]），子分頁切換保留選中。第二輪最強骨架。
- **3a 選中+批次**：開場即「Review all groups」總覽（永不空白）、
  多選翻批次編輯器（混值 —）、底部常駐 Convert All/Export All。
  三項修復全部命中原案要害。
- **3b 選中+釘選**：機制成立（凍結釘選、上限 2、汰舊），但「編輯的是
  誰」的凍結語意有認知成本，且 1280 寬下四欄擁擠。落選。
- **5a 舞台+預置**：per-mode 記憶 + [Minimal][Review][Export][Custom●]
  預置列 + Split 分割視圖，把折疊成本轉為刻意狀態。第二輪並列強案。
- **5b 舞台+萬能找**：●N 修改徽章是廉價高價值的通用機制；Ctrl+K 面板
  本身成立但與預置列疊加會堆概念。徽章被抽出併入兩個混合案。

## 混合案（協調者裁量）

- **H1 工作台演化** = 2b 骨架 + 3a 批次引擎與永不空白 + 5b 徽章 +
  2a 迷你佇列。設計意圖：現行 workbench 的成熟形態——熟悉的三欄節奏
  住進空間分頁裡，冷靜靠分區而非靠藏。
- **H2 舞台演化** = 5a 骨架 + 5b 徽章（不收命令面板）+ 3a 底部大動詞
  與批次覆寫。設計意圖：邊看邊調的集大成，折疊但狀態可讀。
- 3b 釘選不進混合（理由同上）；R2-1/R2-4 無可搶救的核心機制。

## 三備選（最終）

1. **H1 工作台演化**（主推）——理念「熟悉的分區」：對業主既有肌肉記憶
   零破壞，模型/貼圖徹底分頁，新四功能各有明顯的家，批次直擊高頻
   工作型態；egui 實作成本最低（現有面板重新編組 + 子分頁 + 徽章）。
2. **H2 舞台演化**——理念「看著做」：與 H1 形成真實二選（參數導向 vs
   預覽導向），若未來預覽功能成為日常主軸，此案上限更高；實作成本
   中等（大 viewport + 折疊面板記憶）。
3. **3a 選中+批次**——理念「選中即上下文」：與兩混合案哲學真正不同的
   第三極；資產樹導航對「一次只關心一個資產」的心流最順；保留它讓
   業主的選擇覆蓋三種本質不同的操作哲學，而非同一哲學的三個變體。
